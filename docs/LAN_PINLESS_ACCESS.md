# LAN内のWeb PIN不要アクセス

FrameDeckは自宅の信頼できるローカルネットワークでの利用を想定しています。
Web PINが初回のLinuxワーカーペアリング時に自動生成され、後の
iPhoneなど別ブラウザからログインできなくなる問題を解消しました。

## 使い方

QNAPとLinuxの両方のFrameDeckを更新したあと、iPhone等のブラウザで
サーバーの**プライベートLAN IPアドレスを直接指定**して開きます。
例: `http://192.168.68.200:9000`。

- 初回からWeb PINを生成せず、以前のWeb PINが保存されていても
  直接LANアクセスではログイン画面を出しません。
- 漫画/動画の閲覧だけでなく、設定画面、明示的なLinux/QNAPペアリングの
  申請・承認もWeb PINなしで行えます。
- ユーザーはワーカー共有キーの生成・コピー・入力を行う必要がありません。
  共有キーは両端で認証付きの確認番号を照合した後、自動生成・保存されます。
- 保存済みWeb PIN自体は削除しません。外部向けのアクセスが必要な管理者は、
  別途既存Web PIN方式を使用できます。

## セキュリティ上の制約

**重要:** PIN不要とは、同一LANからアクセスできるほかの端末もFrameDeckの
設定・メタデータなどへアクセス可能になることです。信頼できる自宅LANでのみ
使用し、ゲストWi-Fiや公衆インターネットへポート9000を公開しないでください。

PIN不要扱いは、接続元TCPアドレスとブラウザのHostがどちらも直接の
プライベートLAN IPである場合に限ります (IPv4 RFC1918、
IPv6 ULA、同一ホストのloopback)。ホスト名/DNSリバインディング、
プロキシ転送ヘッダー、公開IP、Tailscaleの100.64/10アドレスには
PINなしアクセスの例外を適用しません。APIの変更操作はブラウザの
クロスサイト要求や不一致Originを拒否します。

アプリをLAN上でリバースプロキシの後ろに置くと、実TCP接続元が
プロキシIPになるため、設定によっては認証の境界が変わります。
FrameDeckをインターネットから到達可能なリバースプロキシの後ろに
配置しないでください。HTTPSは認証の代わりではありません。

内部設定 `lan_pinless_access` は既定で `true` です。
明示的に `false` にする場合、Web PINがすでに設定されている
ことを必須とします。既存のWeb PINを忘れている場合、これを
無効にする前にlocalhost管理画面から適切に再設定してください。

QNAPの原本ファイル、SQLite、閲覧履歴、動画変換の認証方式や
データ権限は変更しません。Linuxワーカーとの初回鍵交換は従来どおり
6桁確認番号の両端目視照合と承認が必要です。
