# Webブラウザだけで QNAP と Linux を安全に登録する

FrameDeck v2.4.22 までは共有認証キーの64桁文字列をLinux環境変数へ
コピーする必要がありました。新方式ではその作業は不要です。

## 初回ペアリング

1. LinuxのFrameDeckをWebブラウザから開き、設定の
   「このLinuxを接続待機にする」を押します。Web PIN未設定の場合は
   初回だけ安全な管理PINを自動生成してブラウザをログイン状態にします。
   認証文字列の入力はペアリング作業に不要です。初期管理PINは
   別のブラウザでのログインに必要になることがあるため、
   再表示できない復旧用情報として、安全に保管してください。
   待機は2分だけで自動終了します。
2. QNAPのFrameDeck設定で「安全にLinuxを登録」を押します。QNAP側でも
   待機を開始すると、同一LANのLinux候補IPが一時的に表示されます。
   接続するLinuxを選択します。候補が複数なら正しいIPの端末を選びます。
3. LinuxとQNAPの両画面に出た**6桁の確認番号が完全に一致する**ことを
   比較します。一致しない場合は両方で承認せず、待機を終了させてください。
4. 同じ番号であることを確認したうえで、Linux側の「承認」、続いてQNAP側の
   「接続を確定」を押します。接続用の256ビット認証キーは双方が
   一時的なX25519鍵交換/HKDFで自動生成します。
   **ユーザーに秘密鍵を表示したり、文字列をコピーさせたりしません。**
5. QNAPの「接続済み」を確認します。以後、Linuxの再起動やIP変更は
   認証付きのLAN自動発見で対応します。

初回はLinux/QNAP双方の管理画面で承認が必要ですが、鍵の入力・
Linuxの環境変数設定・QNAPへのSSHは不要です。

## 安全性と制限

- LANに居るだけの機器は登録されません。短期ペアリング窓、厳密な
  LAN IPv4制限、QNAPでの候補選択、両側の明示承認、同一6桁番号の
  人間による照合が必要です。確認番号は入力用PINでも秘密鍵でもありません。
- 実際の共有秘密はLAN上を送信しません。双方でX25519、HKDF-SHA256を
  使って導出します。完了APIは秘密から作ったHMAC認証データのみを交換。
  認証済みの後続Worker処理には従来のHMAC署名・リプレイ防止を使用。
- 6桁番号を**照合せずに**承認する場合、初回LAN内でのなりすましを
  完全には防げません。異なる番号を表示した場合は承認しないでください。
- 認証情報はQNAP/LINUXとも権限0600で原子的に保存します。
  Linuxはcluster-worker-secret.jsonを読み込み、再起動後も再利用します。
  認証情報は通常の設定/status API、URL、ブラウザ保存領域、画面、
  ログに公開しません。
- QNAPにはcryptographyのX25519/HKDF実行環境をQPKGへ同梱します。
  Linuxで `python3 FrameDeck.py` を使うと、FrameDeck自身の
  `FrameDeck_venv` 内にcryptographyが無ければ既存の依存関係の
  自動セットアップ機構で導入します。`python -m framedeck` でも、
  **FrameDeck専用の管理下venvで起動している場合だけ**不足を補います。
  ユーザーによる共有キー管理や手動pip入力は通常不要です。
  QNAPの同梱Pythonや外部のシステムPython/別アプリ管理下venvには
  pipを実行しません。オフラインまたは依存導入失敗時には
  メディア閲覧機能を継続し、ペアリングは安全側で無効のままです。
  **NAS起動時のビルド、npm build、任意のコマンド実行APIは追加しません。**
- LANブロードキャストを遮断するVLAN/ゲストWi-FiやTailscaleだけの
  ネットワークでは候補が現れません。接続先や鍵の自動信頼を推測しません。
  手動方式は折りたたんだ上級者向け項目に残します。
- Webの接続先がHTTPの場合、ユーザーのWeb PIN認証やその他の通信は
  エンドツーエンド暗号化されません。信頼できないネットワークではHTTPSを
  使用してください。HMACによるworker認証は動画ペイロード全体の暗号化を
  意味しません。
- 初回登録だけで高速変換は有効になりません。Linux側の動画ライブラリを
  OSレベルの読み取り専用マウントとして登録し、QNAPの
  「Linux高速変換を使用」を明示的に有効化する必要があります。
- QNAPが動画やSQLiteの正本です。Linuxには元ファイルの書込権限、
  任意コマンド実行、NAS DB更新、全メディア同期権限を与えません。

## 再接続と再登録

認証済みワーカーはLinuxが起動すると自動検出されます。
意図的に別のLinuxへペアリングし直す場合は管理画面で旧登録を解除し、
新たに2台の画面で番号を比較して承認してください。
QNAPが旧登録を削除してもLinux側の認証情報は自動削除されません。
