# 長時間中断後の漫画再開

## 確認した問題

ブラウザの非表示・ページ復元時に漫画APIと先読みを中断・再同期する処理がなかった。ページ送りのfetchに期限がなく、停止中の通信が完了するまで同時実行防止フラグが残る。サーバー再起動やセッション数上限によりメモリ内セッションが消えても、自動復元できなかった。実機通信ログは未取得で、NASのディスク休止等が寄与する可能性は未確認。

## 設計

- visibilitychange（非表示）とpagehideで漫画通信をAbortControllerにより中断し、先読みを破棄する。
- 世代番号を進め、旧応答や旧処理のfinallyが復帰後の状態を変更しないようにする。
- 表示復帰・BFCache復元時に操作を待たずセッションのGETで同期する。
- GETが404の場合のみ、保持しているroot_item_id・entry_idで作り直し、表示モード・綴じ方向・page_indexを復元する。
- 漫画操作と復帰の各通信に12秒の期限を設定する。失敗を表示し、次の操作で再同期できるよう制限を解除する。
- タイムアウトしたページ送りは自動再送しない。既に処理済みか不明なため、現在位置をGETしてから次の明示操作を処理する。

## 検証と制限

Node.jsで実際のフロントエンド関数を実行し、中断中の要求のabort、旧要求終了後の解除、セッション消失後の巻・ページ復元、タイムアウト後の再同期を検証する。ブラウザのページ自体が完全に破棄された場合の起動動作は従来どおり。ネットワーク不通、NASのディスク起動やアーカイブ展開の所要時間を短縮する変更ではない。
